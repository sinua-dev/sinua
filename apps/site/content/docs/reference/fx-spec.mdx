An **FX Spec** is a small JSON file that describes a visual completely: the object and pattern, colour, materials, lifecycle states, data bindings and low-power rules. Every platform resolves it with the same engine, so one file renders the same on the web, iOS, Android and React Native. Designers can hand it over, and apps can ship it, load it from a server, or build it in code.

## Structure

- **`fxSpec`** (required): the version, `"1.15"`.
- **`object`** (required) and **`pattern`** (required): what to draw. See the [catalog](/docs/catalog).
- **`size`** (20 · 32 · 64) and **`speed`**: see [Speed & size](/docs/look/speed-and-size).
- **`ink`** (1.8): how present the visual is, `0` to `1` (default `1`). It fades everything, halos included, and a state can patch it — an assistant rests below full ink when idle and comes to full ink when it listens.
- **`color`**, **`gradient`**: see [Colour & theme](/docs/look/color-and-theme).
- **`materials`**: `glow`, `noise`, `pulse`. See [Materials](/docs/look/materials).
- **`params`**: the pattern's own props (the catalog's style props), e.g. `"steps": 5` on a constellation.
- **`bindings`**: map your app's inputs onto values. See [Bindings](/docs/connect/bindings).
- **`states`**: a patch per lifecycle state. See [States vs patterns](/docs/connect/states-vs-patterns).
- **`transitions`** (1.9): how a change between two states animates. See [Transitions](#transitions) below.
- **`rules`** (1.9): pick a state from the app's inputs ("10,000 steps → `goalReached`"). See [Rules](/docs/connect/bindings#rules-the-file-picks-the-state).
- **`accessibility`** (1.9): the view's spoken name and the words per state. See [Accessibility](/docs/performance/accessibility).
- **`performance`**: `maxFps`, and what to shed under low power.
- **`name`**, **`description`**, **`$schema`**: for people and editors.

Point `$schema` at `https://sinua.dev/schema/fx-spec-1.json` and your editor completes and checks the file as you type.

## Versioning

`fxSpec` is `"1.15"`, written as `major.minor` (so 1.10 comes after 1.9). A file declares the version it was written for, and a runtime reads every file of its major version: keys it doesn't know become warnings, and a different major is refused. Declaring a version older than the keys you use is an error (`transitions` in a `"1.8"` file, say), so write `"1.15"` and use whatever this page documents. An older file stays valid and renders the same, with the exceptions from before 1.0: [`object: "edge"`](#removed-the-edge-object) (0.1.0-beta.8), the 1.14 cleanup (0.1.0-beta.9: [the liquid, particles and holographic materials](#removed-three-materials), [the concluding pattern](#removed-the-concluding-pattern) and the character wardrobe) and the 1.15 cleanup (0.1.0-beta.12: [what 1.15 removed](#removed-in-115)). A file that uses a removed section gets an error and isn't drawn, and the message says what to delete. After 1.0, a removal only comes in a major version (FX Spec 2.0), after a minor of deprecation warnings.

### 1.15: light volumes, and the 0.1.0-beta.12 cleanup

1.15 adds eleven patterns to `object: "signal"`: `veil`, `crystal`, `dune`, `comet`, `flow`, `cohesion`, `scan`, `constellation`, `ripple`, `broadcast` and `halo` (see [Signal](/docs/catalog/signal)). They need `"fxSpec": "1.15"`; an older file that names one gets an error at that `pattern`.

<include lang="json" meta='title="signal-keys.fxspec.json"'>../../../snippets/spec/signal-keys.fxspec.json</include>

- **New keys in `params` and `bindings`:** `level` (every signal pattern but `dune`), `quality` (`cohesion`), `accuracy` (`halo`), `blips` (`scan`), `steps` (`constellation`, a whole number from 2 to 8), `progress` (`dune`, `constellation`), `envelope` (`dune`) and `churn` (all eleven).
- **Eleven binding targets:** `progress`, `level`, `quality`, `accuracy`, `audioLevel`, `muted` and the material masters (`glow.strength`, `noise.strength`, `gradient.strength`, `pulse.strength`, `color.mix`). A target the pattern doesn't read is a warning. See [Bindings](/docs/connect/bindings).
- **The examples** that every older version still resolves are three: `voice-assistant`, `voice-assistant-glowing` and `orb-brand-fixed`.
- Older files resolve exactly as before, apart from what is removed below.

#### Removed in 1.15

Every item is an error at every version, with a message that names the replacement where there is one and otherwise says to delete it from the file.

- **The objects `ring`, `core` and `beacon`**, with all their patterns (`completing`, `loading`, `tracking`, `stepping`, `measuring`, `talking`, `generating`, `typing`, `notifying`, `reconnecting`, `locating`, `scanning`, `broadcasting`). `completing`, `tracking` and `measuring` say their job is covered by `crystal` (`level`) or `dune` (`progress`); the others have no replacement. The new `comet`, `flow`, `scan`, `constellation`, `ripple`, `broadcast` and `halo` are new patterns, not aliases.
- **The flat signal patterns:** `signaling`, `waveform` and `scrolling` say to use `veil`, `metering` says `crystal`, and `playing` says `dune`.
- **The character family:** `object: "character"` and the keys `recipe`, `expression` and `palette`. No replacement.
- **The orb's `silhouette`** pattern and key. No replacement.
- **Binding targets and parameters:** `progress0` to `progress3` (and `progress[0]` to `progress[3]`) and the array parameters `progress` and `segment`. `quality` and `accuracy` are new targets of their own, for `cohesion` and `halo`.
- **Materials:** fills, holes, gradient stops and per-vertex stroke colour no longer exist in the paint contract. The materials left are glow, noise, gradient, pulse and colour.

### 1.14: the 0.1.0-beta.9 cleanup

1.14 adds no key. It's the version the 0.1.0-beta.9 cleanup ships under, so a `"1.14"` file is read strictly (its unknown keys are errors).

- **Removed, an error at every version:** the [liquid, particles and holographic materials](#removed-three-materials), the [concluding pattern](#removed-the-concluding-pattern), and the [wardrobe, named palettes and eye styles](#removed-the-wardrobe-named-palettes-and-eye-styles).
- **One value change that reaches every version:** `glowing` zooms in less between voice states (thinking and speaking come closer to listening), so it no longer seems to jump at large sizes.

### 1.11 to 1.13: characters and silhouettes (removed in 1.15)

1.11 added the `character` object, 1.12 character recipes and 1.13 the orb's `silhouette`. All were [removed in 1.15](#removed-in-115). 1.13 also made a voice state a file has no `states` entry for take the built-in voice behaviour, so a file without `states` still listens, thinks and speaks; that stays.

#### Removed: the edge object

`object: "edge"` (the screen-edge glow, `SinuaEdge`, `<sinua-edge>`) was removed in 0.1.0-beta.8. A file with it fails at every version, with an error at `/object`. There's no replacement: draw a screen-edge glow in your app. It was the first removal before 1.0 (see [Versioning](#versioning)).

#### Removed: three materials

The `liquid`, `particles` and `holographic` materials were removed in 0.1.0-beta.9 (FX Spec 1.14). A file that uses `materials.liquid`, `materials.particles` or `materials.holographic`, or names `liquid` or `particles` in `performance.lowPower.disable`, is rejected at every version, with an error naming the section. Delete the section; there's no replacement. Under low power the host now turns off glow only.

#### Removed: the concluding pattern

Also in 0.1.0-beta.9: the orb's `concluding` pattern. A file whose `pattern` (or a state's) is `"concluding"` is rejected at every version; pick another pattern.

#### Removed: the wardrobe, named palettes and eye styles

Also in 0.1.0-beta.9: the character wardrobe and cosmetics, the built-in named palettes and the eye styles. They belonged to the character family, which [1.15 removed](#removed-in-115) altogether.

### 1.10: calmer voice states

1.10 adds no keys. It made the built-in voice states calmer: `listening`, `thinking` and `speaking` stopped adding particles (see [How the states look](/docs/connect/voice#how-the-states-look-and-changing-it)). The particles material itself was [removed](#removed-three-materials) in 0.1.0-beta.9, so no version draws them any more.

## Transitions

State changes animate, 0.6 s easeInOut unless the file says otherwise. `transitions` sets the duration and curve per pair of states:

<include lang="json" meta='title="voice-orb-transitions.fxspec.json"'>../../../snippets/spec/voice-orb-transitions.fxspec.json</include>

- **Keys:** `default`, `"from->to"`, `"from->*"` and `"*->to"`, with the names from `states`. The most specific entry wins, field by field: the exact pair, then `from->*`, then `*->to`, then `default`.
- **Fields:** `duration` in seconds, `0` to `10` (`0` cuts), and `curve`: `linear`, `ease`, `easeIn`, `easeOut` or `easeInOut`.
- **What moves:** when both states keep the pattern, the values interpolate and the shape flows; a change of pattern cross-fades (the orb lattice trio, glowing, calibrating and progressing, morphs point by point). The file sets how long and how; the engine picks the technique.
- A view's `crossFade` option, when you set it, overrides every change's duration (`0` still cuts).
