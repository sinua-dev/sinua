The Gemini source streams audio to Gemini Live and plays the model's reply, reporting state and audio to the visual. Long conversations cross Gemini's connection limit transparently through session resumption.

## Credentials

Your server mints an ephemeral auth token (`auth_tokens/…`) with your API key and locks the model, voice and instructions into it, so the client can't change them: `mintGeminiLiveCredential` in `@sinua/voice/server`. Point the source at that endpoint with `credentialUrl`, the same on every platform. See [Credentials](/docs/connect/voice/credentials).

## Good to know

- **Ephemeral tokens only.** With an `auth_tokens/…` token, the source uses Gemini's constrained endpoint automatically. A raw API key is refused on every platform; for local development use `npx @sinua/voice dev-proxy`.
- **Reconnects are handled.** When Gemini announces the end of a connection (`goAway`) or the socket closes, the source resumes the session on a new connection, with a new token from your endpoint.
- **Start from a user gesture on the web**, since the browser only allows the microphone and audio playback after one. On iOS, add `NSMicrophoneUsageDescription`; on Android, declare `RECORD_AUDIO`. **Say where the audio goes:** the user's voice is sent to Google, so your iOS purpose string (and, on Android, the explanation you show before the system prompt, which carries no app text) should say so. For example: "Your voice is sent to Google so the assistant can hear you." App Store review expects the purpose string to explain the use.
