# Android / Kotlin

## `packages/android` — the Gradle library module

A standalone Gradle project (own `settings.gradle.kts`, own wrapper) producing an Android library module wrapping a UniFFI-generated Kotlin binding around native `.so` builds.

> **No renderer in this module itself** — it only proves `frame(state, size, t)` returns correct data (see *Testing* below), and a consumer of just this library still gets an `OrbFrame` (dots/lines) and has to paint it themselves. The Jetpack Compose renderer is the `:sinua-view` module (*Rendering* below).

```
packages/android/
├── build.gradle.kts
├── gradlew / gradle/wrapper/          # own copy (Gradle 8.9)
├── src/main/
│   ├── kotlin/uniffi/core_engine/     # gitignored, UniFFI-generated, regenerated by build.sh
│   └── jniLibs/{arm64-v8a,armeabi-v7a,x86_64,x86}/libcore_engine.so   # gitignored, regenerated by build.sh
└── src/androidTest/kotlin/.../GoldenTests.kt   # hand-written, tracked (+ SinuaGoldenTests.kt: all spec/sinua-golden.json cases, bundled as androidTest assets from spec/; FxSpecTests.kt: every spec/examples FX Spec)
```

### Toolchain: NDK + `cargo-ndk`

Rust→Android cross-compilation needs the Android NDK (installed once via `sdkmanager --install "ndk;27.0.12077973"`, landing at `/opt/homebrew/share/android-commandlinetools/ndk/27.0.12077973` on this setup) and [`cargo-ndk`](https://github.com/bbqsrc/cargo-ndk), which wraps `cargo build` with the correct NDK linker/toolchain flags per target — hand-wiring `.cargo/config.toml` linker paths per ABI is the alternative and is not worth it.

The four Android ABIs map to Rust targets as: `arm64-v8a`→`aarch64-linux-android`, `armeabi-v7a`→`armv7-linux-androideabi`, `x86_64`→`x86_64-linux-android`, `x86`→`i686-linux-android`. All four are listed in the workspace-root `rust-toolchain.toml` for the same reason iOS's targets are — see [`ios.md`](ios.md#build-pipeline-buildsh).

### Build pipeline (`build.sh`)

```bash
export ANDROID_NDK_HOME=/opt/homebrew/share/android-commandlinetools/ndk/27.0.12077973  # build.sh defaults to this
packages/android/build.sh
```

1. Host dylib build + `uniffi-bindgen --language kotlin` (same shape as iOS's step 1–2).
2. `cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 -t x86 -o src/main/jniLibs --platform 24 build --release` — cross-compiles all four ABIs and copies the `.so` files directly into the Gradle module's `jniLibs` source set. `--platform 24` is the minSdk floor this crate targets (see `build.gradle.kts`).

### Gradle setup notes

- `android.useAndroidX=true` in `gradle.properties` is required — omitted once, produced a real build failure (`checkDebugAndroidTestAarMetadata`) rather than a silent issue, because `androidx.test` dependencies were pulled in without it.
- `net.java.dev.jna:jna:5.14.0@aar` is a required runtime dependency — UniFFI's Kotlin bindings call into native code through [JNA](https://github.com/java-native-access/jna), not raw JNI directly.
- `compileSdk = 36` with AGP 8.7.3 needs `android.suppressUnsupportedCompileSdk=36` in `gradle.properties` (AGP 8.7.3 predates official compileSdk 36 support; compiles fine with a warning otherwise).

### Voice: `dev.sinua.voice`

The native audio pipeline (mic and test tone → the engine's voice opts)
lives in the same library module, with no new runtime dependency. The
library manifest does **not** declare `RECORD_AUDIO`. An app that uses
`LocalMicVoiceSource` declares it and requests it at runtime first;
`isMicPermissionGranted(context)` checks.

```kotlin
val source = LocalMicVoiceSource()             // or TestToneVoiceSource()
val voice = VoiceOverrides.bind(source)        // Orb: VoiceOverridesOptions(bandEaseRate = Double.POSITIVE_INFINITY)
source.connect()                               // SecurityException without RECORD_AUDIO
// per frame:
val frame = frameWithOverrides("speaking", 64u, t, knobs + voice.overrides(dt))
```

The byte spectrum, band math and `VoiceOverrides` are checked against
Chrome/Web's own output by JVM unit tests (`src/test/…/VoiceGoldenTest.kt`
against `spec/voice-golden.json`: `ANDROID_HOME=… ./gradlew
testDebugUnitTest`). Design, parity method and permissions are in
[`../audio-pipeline.md`](../audio-pipeline.md#native-iosandroid-mic--test-tone-built-spec-exact-parity-with-web).

### Rendering: the `:sinua-view` module (`dev.sinua.view`)

A drop-in Compose view, in its own Gradle module
(`packages/android/view`) so the core library stays Compose-free. It holds
the paint contract (`fxInk`, `paintFxFrame`); the Studio's `ink` /
`paintFrame` delegate to it.

```kotlin
FxView(spec = specJson, voice = micSource, modifier = Modifier.size(160.dp))
```

It runs a `withFrameNanos` loop gated on lifecycle ≥ RESUMED and follows
`isSystemInDarkTheme` and "Remove animations". Its instrumented tests
(`./gradlew :sinua-view:connectedDebugAndroidTest`) cover raster parity
with the old Studio painter, the spec math, and a Compose render. See
[`../fx-view.md`](../fx-view.md).

### Testing

`src/androidTest/kotlin/.../GoldenTests.kt` runs as an **instrumented** test, not a JVM unit test — the `.so` files are real Android ELF binaries and cannot load on the host JVM the way a `testDebugUnitTest` run would need. Requires an actual emulator or device:

```bash
$ANDROID_HOME/emulator/emulator -avd <name> -no-window -no-audio -no-boot-anim &
# wait for `adb shell getprop sys.boot_completed` == 1
./gradlew connectedDebugAndroidTest
```

Same scope as iOS's `GoldenTests.swift`: proves the Kotlin → JNA → C → Rust → C → JNA → Kotlin round-trip, not a full re-run of the Rust suite. See [`../testing.md`](../testing.md).
