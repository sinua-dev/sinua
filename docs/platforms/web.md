# Web / TypeScript

## `packages/core` — the published surface

`@sinua/core` is the TypeScript package other web code depends on. It has no logic of its own beyond typed wrappers — the actual geometry is in Rust, compiled to WebAssembly.

```
packages/core/
├── pkg/            # wasm-pack output (gitignored, regenerated by `npm run build`)
├── src/index.ts     # hand-written typed wrapper -- the only source file
└── dist/            # tsc output (gitignored)
```

### Build pipeline

```bash
cd packages/core
npm run build   # = npm run build:wasm && tsc -p tsconfig.json
```

`build:wasm` runs `wasm-pack build --target web --out-dir ../../packages/core/pkg` from `crates/core_engine`, then `scripts/inline-wasm.mjs`, which does three things:
- It writes `pkg/sinua_core_inline.js`: the wasm as raw DEFLATE + base64 (~320 KiB), inflated by [fflate](https://github.com/101arrowz/fflate) (MIT, bundled in with esbuild, listed in `THIRD_PARTY_LICENSES`) and instantiated with `initSync` when the module is imported. `src/` imports the engine from that file, so the API stays synchronous.
- It strips the glue's `new URL('…_bg.wasm', import.meta.url)` fallback, so bundlers don't also emit an unused 729 KB asset.
- It removes wasm-pack's `pkg/.gitignore`. That file is `*`, and `npm pack` honours it: before this, the packed package shipped no wasm at all. `test/pack.test.mjs` guards against that coming back.
- It removes wasm-pack's `pkg/package.json`. Its `"sideEffects": ["./snippets/*"]` told bundlers that the inline module had no side effects. esbuild and Rollup (so every Vite production build) then dropped it, `initSync()` included, and the first engine call threw `reading '__wbindgen_free'`. The tarball never shipped that file, but `file:` consumers (the Studio, the bench) read it. families caught this; the dev server and my Angular/webpack tarball runs had missed it. `bundler-check/` bundles a one-call consumer with esbuild, Vite and webpack in production mode, for the packed tarball and for the working tree, and runs each bundle. It fails 3/3 with the old file back in place. CI runs it in the web job.

**Why inline** (2026-09-20, measured on a scratch `ng new` Angular 21 app):
- The old `--target bundler` glue needs a bundler that implements the wasm/ESM integration. Angular's application builder rejects it in every Zone.js app ("WASM/ES module integration imports are not supported with Zone.js applications").
- webpack 5 needs `experiments.asyncWebAssembly`, and a plain `<script type="module">` can't load it at all.
- A URL-loaded `--target web` build would need `await init()` plus, in Angular, a manual asset entry: the builder keeps `new URL(…, import.meta.url)` but doesn't copy the file, so it returns 404.
- The inline build loads with no configuration in Angular (Zone.js and zoneless), webpack 5 (no `experiments`), Vite, a plain module script and node (no flags).
- Its cost: about +55 KB gzip over a separate wasm file (≈300 KB for an Angular app's main bundle), plus a synchronous compile. Chrome 151 compiles the 729 KB module in 2.8 ms on the main thread.
- CSP: pages need `'wasm-unsafe-eval'`, as with any wasm.

### API (`src/index.ts`)

```ts
frame(state, size, t): OrbFrame | null
frameWithOverrides(state, size, t, overrides): OrbFrame | null
frameTransition(fromState, toState, size, t, blend): OrbFrame | null
resolvedOpts(state, size): ResolvedPreset | null
resolveFxSpec(spec | json, ctx?): FxSpecResolved     // FX Spec, see ../fx-spec.md; ctx = { state?, inputs?, lowPower? }
frameFromFxSpec(spec | json, elapsed, ctx?): OrbFrame | null
new FxSpecPlayer(spec, opts?)                        // 1.1 caller loop: setState / setInput / frame(elapsed, dt)
fxColorToHsl(color): FxHsl | null
estimateCost(state, size, overrides?): FxCost | null // render-cost proxy, light/medium/heavy (../engine.md#cost-estimate)
fxSpecCost(spec | json, ctx?): FxCost | null
framePacked / frameWithOverridesPacked / frameFromFxSpecPacked → PackedFrame | null
unpackFrame(packed): OrbFrame | null                 // readPacked(packed, visitor): paint with no objects
```

### Frame transport: packed `Float64Array` (2026-09-18)

`frame`, `frameWithOverrides` and `frameFromFxSpec` cross the wasm boundary as **one packed `Float64Array`**. wasm-bindgen copies it out of linear memory once, and it is unpacked into the same `OrbFrame` objects as before. The old path, `serde_json` → string → `JSON.parse`, was measured at 10–25× the frame's own compute. The public API didn't change, and the output is **bit-identical**: it's f64 throughout, and `test/packed.test.mjs` checks all 214 golden cases plus every FX Spec example. The JSON bridge stays as `frameViaJson` / `frameWithOverridesViaJson` / `frameFromFxSpecViaJson` (and the raw `*_json` exports).

Layout v1 (`crates/core_engine/src/transport.rs`, `src/packed.ts`):

| Section | Size | Fields |
|---|---|---|
| header | 7 | `version, colorMode (0 ink / 1 fixed), nDots, nLines, nPolylines, nPoints, found (0 = null)` |
| dots | `nDots × 8` | `x y z r white a saturation hue` |
| lines | `nLines × 9` | `x1 y1 x2 y2 white a w saturation hue` |
| polylines | `nPolylines × 6` | `white a w saturation hue pointCount` |
| points | `nPoints × 2` | `x y` (each polyline's points, back to back) |

**Layout v2** (materials phase 1) is emitted **only** for frames with fills or effect runs; every other frame is still v1, byte for byte:
- The header grows to 11: `[2, colorMode, nDots, nLines, nPolylines, nPoints, found, nFills, nFillPoints, nStops, nEffects]`.
- v1's sections are unchanged.
- Then fills × 14 `white a saturation hue blur blend pointCount gradKind (-1 none / 0 linear / 1 radial) x0 y0 x1 y1 r stopCount`, fill points × 2, stops × 5 `offset white a saturation hue`, and effects × 5 `target start count blur blend`.
- `asPacked` / `unpackFrame` / `readPacked` read both versions. `readPacked`'s `fill(data, at, pointsAt, stopsAt)` visitor runs first, because fills paint under everything.

**Layout v3** (materials phase 2) is emitted **only** when some fill has holes; otherwise v2 or v1 as above:
- The header grows to 12 (v2's 11 + `nHoleRings`).
- Fills are × 15 (v2's 14 + `holeRingCount`).
- After the fill points come a hole-ring table (`nHoleRings` point counts), then the hole points × 2. Stops and effects follow as in v2.
- `readPacked`'s `fill` visitor gets `holes: { ringsAt, pointsAt }` for such fills.

**Layout v4** (per-vertex stroke colour, 2026-09-19) is emitted **only** when some polyline has `hues`; otherwise v3, v2 or v1 as above:
- It is v3 exactly, with every section present even if empty.
- The header grows to 13 (v3's 12 + `nPolyHues`).
- After the effects come a table of `nPolylines` hue counts (0, or that polyline's pointCount), then the hues back to back.
- `unpackFrame` sets `polyline.hues`, and `readPacked`'s `polyline(data, styleAt, pointsAt, count, huesAt?)` visitor gets `huesAt` for such strokes.
- Paint rule: [`engine.md`](../engine.md#per-vertex-stroke-colour-2026-09-19).

A painter can skip objects entirely: `readPacked(packed, { polyline, line, dot })` hands each primitive's offset into `packed.data` in paint-contract order.

A zero-copy `Float64Array::view` into wasm memory was rejected. It's `unsafe`, and the js-sys docs say it's invalidated by "any future calls to `Box::new` (or malloc of any form)"; it would save a ~33 KB copy that doesn't show up in the numbers.

**Measured** with `bench/transport.mjs` (node 24) and the same code in headless Chrome 151, M-series Mac. The figures are median ms per frame at size 64:

| case | elements | JSON (node) | packed + unpack (node) | JSON (Chrome) | packed + unpack (Chrome) |
|---|---|---|---|---|---|
| `working` | 516 | 1.02 | 0.13 | 0.82 | 0.11 |
| `working` + glow | 2014 | 3.60 | 0.21 | 3.02 | 0.20 |
| `breathing` + glow | 2420 | 4.39 | 0.25 | 3.59 | 0.26 |
| `metering` | 96 | 0.16 | 0.010 | 0.13 | 0.009 |
| `scrolling` | 40 | 0.09 | 0.012 | 0.08 | 0.011 |

That is 7–18× less time per frame. Chrome rounds `performance.now()` to 0.1 ms without cross-origin isolation, so the Chrome figures are batch averages. Painting is now the dominant Web cost, and that is `@sinua/web`'s side.

The other wasm exports still return JSON, which is fine because they are not per-frame (`resolveFxSpec`, `resolvedOpts`, cost, colour). See [`architecture.md`](../architecture.md#the-uniffi--wasm-bindgen-split) for the original JSON-over-the-wire decision.

`src/voice.ts` (re-exported from the same entry point) adds the voice
contract on top, with no wasm involved: the `VoiceSource` / `AgentState` /
`VoiceMetrics` types, `VOICE_STATE_CODE`, and `VoiceOverrides` /
`voiceOverrides` — the helper that turns a live voice reading into the
exact overrides object `frameWithOverrides` expects. That includes
`interruptAge`, fed by `VoiceSource.onInterrupt` (optional) or by
`VoiceOverrides.interrupt()`. DOM-free, so it is usable outside a browser
too. See [`audio-pipeline.md`](../audio-pipeline.md#wiring-a-voicesource-into-orbsignal--the-voiceoverrides-helper).

### Consuming it from another local package

A local consumer (an app next to a checkout) depends on `@sinua/core` via `"file:…/packages/core"` in its `package.json`. Two consequences:

- **Always run `packages/core`'s build before a consumer's** — the consumer's `node_modules/@sinua/core` is a symlink to the real package directory, so a stale `pkg/`/`dist/` there is a stale build everywhere. Each consumer's own `build.sh` does this automatically.
- **Vite needs the symlinked directory allow-listed.** Vite's dev server won't serve files outside its project root by default, even through a symlink — add the package directory to `server.fs.allow` in the app's `vite.config.ts`. (Metro has the equivalent problem for the React Native example app — see [`react-native.md`](react-native.md).)

## `packages/web` — the renderer (`@sinua/web`)

The Web painter and a drop-in view. `packages/core` stays DOM-free (its
tsconfig has no DOM lib, and `voice.ts` runs under plain node), so canvas
code lives here instead.
- `drawFrame` / `drawCrossDissolve` / `ink`: the paint contract, moved
  verbatim from the Studio, which now imports it from here.
- `mount(canvas, options)` returns a handle with `update` / `pause` /
  `resume` / `destroy`. It's framework-agnostic.
- `@sinua/web/react` exports `<FxView/>`. React is an optional peer; the
  root entry never imports it.

```ts
import { mount } from "@sinua/web";
mount(canvas, { spec, voice });
```

Options, paint rules and the Studio-parity proof are in
[`../fx-view.md`](../fx-view.md). `npm test` (node, stubbed browser APIs)
and `npm run example` (a Vite page with the three one-liners) run from
`packages/web`. It depends on `@sinua/core` as a peer (the Studio links
both with `file:`).

## `apps/smoke` — removed (2026-09-18)

There used to be a bare single-HTML wasm sanity page here (`--target web`, a
`<select>` of the 9 ported orb states, grayscale only). It carried its own
inline copy of the paint contract, which could drift from
the Studio's, and it couldn't import that shared TypeScript module without a
bundler. What it proved is now covered elsewhere: `packages/core`'s node tests
run the wasm end to end, and `packages/core/bundler-check` runs the bundler
builds. It was deleted rather than migrated (2026-09-18).

> **Only Canvas2D is used.** The original plan mentioned WebGL and CSS `@property`/`offset-path` as options; neither was needed for dot/line geometry this simple, so neither exists here. If a future family needs GPU rendering, that's new work, not something to assume is already wired up.
