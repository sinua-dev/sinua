An **FX Spec** is a small JSON file that describes a visual completely: the object and pattern, colour, materials, lifecycle states, data bindings and low-power rules. Every platform resolves it with the same engine, so one file renders the same on the web, iOS, Android and React Native. Designers can hand it over, and apps can ship it, load it from a server, or build it in code.

## Structure

- **`fxSpec`** (required): the version, `"1.12"`.
- **`object`** (required) and **`pattern`** (required): what to draw. See the [catalog](/docs/catalog).
- **`size`** (20 · 32 · 64) and **`speed`**: see [Speed & size](/docs/look/speed-and-size).
- **`ink`** (1.8): how present the visual is, `0` to `1` (default `1`). It fades everything, halos included, and a state can patch it — an assistant rests below full ink when idle and comes to full ink when it listens.
- **`color`**, **`gradient`**: see [Colour & theme](/docs/look/color-and-theme).
- **`materials`**: `glow`, `noise`, `pulse`, `liquid`, `particles`, `holographic`. See [Materials](/docs/look/materials).
- **`params`**: the pattern's own props (the catalog's style props), e.g. `"ringCount": 3`.
- **`bindings`**: map your app's inputs onto values. See [Bindings](/docs/connect/bindings).
- **`states`**: a patch per lifecycle state. See [States vs patterns](/docs/connect/states-vs-patterns).
- **`transitions`** (1.9): how a change between two states animates. See [Transitions](#transitions) below.
- **`rules`** (1.9): pick a state from the app's inputs ("10,000 steps → `goalReached`"). See [Rules](/docs/connect/bindings#rules-the-file-picks-the-state).
- **`accessibility`** (1.9): the view's spoken name and the words per state. See [Accessibility](/docs/performance/accessibility).
- **`performance`**: `maxFps`, and what to shed under low power.
- **`name`**, **`description`**, **`$schema`**: for people and editors.

Point `$schema` at `https://sinua.dev/schema/fx-spec-1.json` and your editor completes and checks the file as you type. A [character recipe](/docs/reference/character-recipe) inside it is checked too.

## Versioning

`fxSpec` is `"1.12"`, written as `major.minor` (so 1.10 comes after 1.9). A file declares the version it was written for, and a runtime reads every file of its major version: keys it doesn't know become warnings, and a different major is refused. Declaring a version older than the keys you use is an error (`transitions` in a `"1.8"` file, say), so write `"1.12"` and use whatever this page documents. An older file stays valid and renders the same, with one exception: [`object: "edge"`](#removed-the-edge-object) was removed during the beta.

### 1.12: character recipes

1.12 lets a file carry its own [character](/docs/catalog/character): the new key **`recipe`** holds a character recipe, the same format as the built-in characters. No code and no Sinua release; the file is the character. [Make your own character](/docs/catalog/own-character) walks through one, and the [recipe reference](/docs/reference/character-recipe) lists every key.

<Demo spec="spec/custom-character.fxspec.json" controls={[{ state: ["idle", "listening", "thinking", "speaking"] }]} />

```json title="custom-character.fxspec.json (shortened)"
{
  "$schema": "https://sinua.dev/schema/fx-spec-1.json",
  "fxSpec": "1.12",
  "object": "character",
  "pattern": "pip",
  "recipe": { "recipe": 1, "id": "pip", "profile": "chirp", "palette": { … }, "rig": { … }, "parts": [ … ], "burst": { … } },
  "params": { "seed": 5, "flutterGain": 0.3 }
}
```

- **`recipe`** needs `"fxSpec": "1.12"` and `object: "character"`. The `pattern` (and any state's) names the recipe's `id`, which can't be a built-in character's. Its mistakes point into it: `/recipe/parts/2/segments: expected a whole number from 3 to 128`.
- **Limits**, so a file from outside can't make the engine slow: at most 64 KB, 48 parts, lists of 32, numbers within ±1000. Over a limit is an error, never trimmed; a recipe that would be heavy to draw is a warning.
- **Shapes from a drawing:** any shape in a recipe may be an SVG path, `"shape": { "path": "M50 74 L56 22 … Z" }`, with the commands `M L H V C S Q T Z` (no arcs) in the 200-unit box; later subpaths are holes.
- **Voice states:** a recipe moves like the shared character, or like a built-in with `"profile": "chirp"`. The file's own `states` go on top.
- **`expression`** (any character): `"happy"`, `"surprised"`, `"thoughtful"`, `"sad"`, `"sleepy"` or `"none"`, in the base and in `states`. A state change blends one into the next.
- **`palette`** (any character): `{ "<slot>": "<colour>" }`, hex or DTCG, in the base and in `states`. See [Palette](/docs/catalog/character#palette).
- 1.8–1.11 files resolve exactly as before.

#### Removed: the edge object

`object: "edge"` (the screen-edge glow, `SinuaEdge`, `<sinua-edge>`) was removed in 0.1.0-beta.8. A file with it fails at every version, with an error at `/object`. There's no replacement: draw a screen-edge glow in your app. It's the one time a minor version took something away, during the beta; after 1.0 a removal only comes in a major version (FX Spec 2.0), after a minor of deprecation warnings.

### 1.11: characters

1.11 adds one object, **`character`**: a [face for a voice assistant](/docs/catalog/character). Its voice states are built in, so a file only says who it is:

<include lang="json" meta='title="character.fxspec.json"'>../../../snippets/spec/character.fxspec.json</include>

- **`object: "character"` needs `"fxSpec": "1.11"`.** An older file gets an error at `/object`.
- **No `color` or `gradient` on a character.** They would repaint its eyes and screen, so the file gets an error that points at `params.hue`. `hue` turns the character's own colour, and `mouth`, `accessories`, `look`, `turn` and `seed` are its other options.
- **The pose values are `params` too.** The values the states set (`gazeX`, `lid`, `eyeSmile`, …) can go in `params` or in a state's patch, to tune how a state looks.
- **`stateAge`** is a new runtime input: the seconds since the view's state changed. Every view sets it (a character blinks with it as your turn ends), and it can't go in `params`.
- **Older files** (1.8 to 1.10) resolve exactly as before.

### 1.10: calmer voice states

1.10 adds no keys. It changes the built-in look of the voice states: `listening`, `thinking` and `speaking` no longer add particles (see [How the states look](/docs/connect/voice#how-the-states-look-and-changing-it)).

- **A `"1.10"` file:** its voice states have no particles. To keep them, set them in the state's entry: `"listening": { "materials": { "particles": { "strength": 1 } } }`.
- **A `"1.8"` or `"1.9"` file:** renders exactly as before, particles included.
- **A view without a spec** (`pattern` + `state`) follows the current look; `overrides` turns particles back on for that view.

## Transitions

State changes animate, 0.6 s easeInOut unless the file says otherwise. `transitions` sets the duration and curve per pair of states:

<include lang="json" meta='title="voice-orb-transitions.fxspec.json"'>../../../snippets/spec/voice-orb-transitions.fxspec.json</include>

- **Keys:** `default`, `"from->to"`, `"from->*"` and `"*->to"`, with the names from `states`. The most specific entry wins, field by field: the exact pair, then `from->*`, then `*->to`, then `default`.
- **Fields:** `duration` in seconds, `0` to `10` (`0` cuts), and `curve`: `linear`, `ease`, `easeIn`, `easeOut` or `easeInOut`.
- **What moves:** when both states keep the pattern, the values interpolate and the shape flows; a change of pattern cross-fades (the orb lattice trio, glowing, calibrating and progressing, morphs point by point). The file sets how long and how; the engine picks the technique.
- A view's `crossFade` option, when you set it, overrides every change's duration (`0` still cuts).
