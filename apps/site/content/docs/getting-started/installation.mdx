Every platform ships the same engine: a compiled Rust core (WebAssembly on the web, a native library on iOS and Android) plus a view layer for that platform.

| Platform | Package | What you get |
|---|---|---|
| Web | `@sinua/web` (+ `@sinua/core`) | the view for React, Web Components (Vue, Svelte, Angular, Solid, plain HTML) and a vanilla `mount()` |
| iOS | Swift package `sinua-swift`, products `Sinua` (+ `SinuaVoice`) | SwiftUI and UIKit views; iOS 15+ |
| Android | `dev.sinua:sinua-view` (+ `dev.sinua:sinua-core`) on Maven Central | Jetpack Compose and Android View; API 24+ |
| React Native | `@sinua/react-native`, from source for now | a native view over the iOS and Android views |

Voice sources for LiveKit, OpenAI Realtime, Gemini Live and ElevenLabs are separate: `@sinua/voice` on the web (one entry point per vendor) and one package per vendor on iOS and Android, so an app that doesn't use one never downloads its SDK. See [Voice](/docs/connect/voice).

No bundler configuration on the web: the engine's WebAssembly is inlined into `@sinua/core`, so it works in Vite, webpack, Angular CLI (with Zone.js or zoneless), a plain `<script type="module">` and Node. Pages with a Content Security Policy need `'wasm-unsafe-eval'` in `script-src`.

## Android: 16 KB pages and JNA

Sinua's native libraries are 16 KB aligned, so they run on Android 15+ devices with 16 KB memory pages, as Google Play requires. Sinua uses JNA 5.19.1.

JNA also carries its loader for `armeabi`, `mips` and `mips64`, which makes Play offer your app to devices the engine doesn't support. Leave them out in your app module (the bundle gets about 138 KB smaller; a library can't do this for you):

```kotlin
android {
    packaging {
        jniLibs { excludes += listOf("lib/armeabi/**", "lib/mips/**", "lib/mips64/**") }
    }
}
```

## Web: dev tools in `@sinua/core/dev`

What only a studio, a dev tool, a test or a demo needs lives in its own entry, so your app doesn't ship it: `estimateCost`, `fxSpecCost`, `parameterCatalog`, `checkOverrides`, the conversation samples and `SimulatedVoiceSource`.

```ts
import { estimateCost, SimulatedVoiceSource } from "@sinua/core/dev";
```

`@sinua/core/dev` also re-exports everything in `@sinua/core`. A tool that loads catalog packs or recipes should import everything from it, so it runs one engine. On iOS and Android these functions are only in development builds, not in the published packages.

## From source

To build the packages yourself (or React Native, which isn't on npm yet), clone the repository and build them for your platform. Each package's build script regenerates the bindings from the engine.
